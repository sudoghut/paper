## 一、论文是干什么的？

现在的 AI 智能体已经不只是回答问题，而是能写网页、做 PPT、建 CAD 模型、渲染 Blender 场景。但真实的办公工作有两个难点：一是任务本身很复杂，要反复推理、调用工具、自己检查；二是工作时间很长，比如盯着一次要跑好几天的训练、跨好几次对话推进一个项目，中途还会被打断。论文把这两点叫作「任务复杂度」和「时间跨度」。

论文提出的 CoworkOS 是一个开源的「智能体运行框架」（harness，可以理解为给大模型配的一整套办公室：工位、同事、文件柜、备忘录和值班表）。它想回答的问题是：一个 AI 同事能不能既把复杂活干好，又能长期盯着事情，还让人随时插手修改同一份成果？论文还用它做了一个长期案例：让它自动给 Qwen3.6-35B-A3B 做五轮后训练，八个基准的平均分从 33.19 升到 42.95。

需要说明：这是一份技术报告式的论文，署名为 CoworkOS Team，所有结果都是作者自己的报告，没有独立复现。

## 二、核心方法与创新

可以把 CoworkOS 想成一家小公司，设计思路是「模型管策略，运行时管执行」：

**1. 三层结构**（类比：项目经理、调度员、外包员工）

- Main Agent（主智能体）：对用户负责的项目经理。它理解需求、拆任务、自己动手或委派，并验收最终成果。它的决策可写成 $a^M_t \sim \pi^M(\cdot \mid g, h^M_t, F_t)$（论文式 3），其中 $g$ 是目标，$h^M_t$ 是历史，$F_t$ 是新反馈。
- Coordinator Runtime（协调运行时）：调度员。它给每次委派分配稳定编号，维护队列、租约和确认，让消息即使在中断后也不丢。状态更新写作 $\xi_{k+1}=F_C(\xi_k,e_{k+1})$（式 5）。
- Subagents（子智能体）：只拿到被授权的上下文和工具，独立完成一块任务，最后交回报告、成果引用和状态，而不是把整条思考轨迹都塞给 Main。委派可以同步（等结果）或异步（先返回编号，结果以后进收件箱）。

**2. 人和 AI 共同编辑同一份成果**（类比：共享在线文档）

平台把文档、幻灯片、参数化 CAD、Blender 工程都当作带版本号的资源 $r=(\iota,\kappa,x,v)$。任何人或智能体提交修改，都要带上自己看到的基准版本 $\hat v$：基准版本等于当前版本就接受并让版本加一，否则返回冲突，不会悄悄覆盖别人的改动（式 7）。这样人直接在成果上改一下，本身就是对 AI 的一种指导。另外，非原生软件可以通过 MCP 接入。

**3. 工作区与语义记忆**（类比：文件柜加交接笔记）

- 分层工作区：Main、各子智能体、每次运行各有自己的目录，成果经 Main 审核后才发布。
- 任务记忆：Main 维护一份记忆文档，写清目标、已完成、下一步和约束；上下文要重置时，按式 10 用记忆、运行状态和近期历史重新拼出上下文。
- Jobs：长时间任务（训练、构建）作为后台作业保留状态和日志；监控脚本用确定性程序对比基线，没变化就不调用模型，节省成本。

**4. 实验账本与 RSI 后训练**

Task 级账本记录实验目标、候选方案和指标，并区分「从运行产生的指标文件读到的数」和「只出现在叙述报告里的数」。RSI（递归自我改进）案例的循环是：评测当前模型，诊断能力缺口并修改数据管线，生成、验证、过滤数据，做 SFT，再评测。

## 三、使用了哪些模型和计算资源？

| 项目 | 论文披露的内容 |
|---|---|
| 基准评测的骨干模型 | GLM-5.3，High thinking effort，256K token 上下文，单次回复最长 64K token。对比的 OpenHands、Codex、DeepSeek Harness 也在同一模型与任务配置下运行 |
| RSI 案例 | GLM-5.3 主要当控制器和数据教师；被训练与评测的模型是 Qwen3.6-35B-A3B |
| 训练方式 | SFT。R0 用 1,345 条工具交互轨迹；每轮训练步数分别为 66、69、10、24、22、20 步，R3 起每轮 4 个 epoch，新数据重复 24 倍 |
| 数据去重 | BM25 任务相似度过滤，阈值 0.8 |
| 评测算力（已披露部分） | MLE-Bench-Lite 每任务 4 CPU、32 GiB 内存、1 块 H200 GPU、5 小时智能体预算；MLS-Bench 同样 5 小时预算，按任务分配 H200（多 GPU 任务 64 GiB 内存）；WorkspaceBench-Lite 每任务 2 CPU、8 GiB、两小时上限；JobBench 单任务超时 7200 秒；tau3 Banking 外层单任务限时 2400 秒 |
| 训练所用 GPU 型号与数量、训练总耗时、每轮耗时、API 调用量与费用 | 论文未披露。论文还特别说明，轮次序号不代表实际耗时 |

## 四、实验结果

12 个基准分四类，下表为论文表 1（数字已用 PDF 核对）。分数越高越好；GDPVal 为 Elo，也是越高越好。

| 类别 | 基准 | OpenHands | Codex | DeepSeek Harness | CoworkOS |
|---|---|---|---|---|---|
| 工具使用 | SkillsBench | 63.30 | 53.48 | 56.75 | 64.34 |
| 工具使用 | tau3-Bench Banking | 40.20 | 46.39 | 55.67 | 49.48 |
| 工具使用 | AutomationBench | 50.50 | 30.33 | 53.50 | 51.83 |
| 工具使用 | 平均 | 51.33 | 43.40 | 55.31 | 55.22 |
| 生产力 | JobBench | 55.02 | 23.42 | 56.15 | 59.88 |
| 生产力 | Harvey Legal Agent Bench | 23.75 | 12.70 | 22.30 | 22.74 |
| 生产力 | GDPVal（Elo） | 1122 | 925 | 1157 | 1164 |
| 生产力 | OfficeQA Pro | 66.20 | 66.30 | 62.30 | 65.90 |
| 生产力 | WorkspaceBench-Lite | 64.54 | 58.81 | 68.76 | 67.14 |
| 生产力 | 平均 | 55.27 | 40.11 | 56.13 | 57.54 |
| 搜索 | WideSearch | 81.43 | 82.05 | 72.48 | 82.47 |
| 搜索 | BrowseComp | 83.00 | 75.50 | 80.80 | 81.80 |
| 搜索 | 平均 | 82.22 | 78.78 | 76.64 | 82.14 |
| ML 编程 | MLE-Bench-Lite | 60.40 | 67.28 | 76.70 | 76.90 |
| ML 编程 | MLS-Bench | 28.91 | 29.05 | 35.57 | 35.62 |
| ML 编程 | 平均 | 44.66 | 48.17 | 56.14 | 56.26 |

大白话解读：CoworkOS 在生产力和 ML 编程两类的平均分最高，在工具使用和搜索上与第一名只差零点几分，所以更准确的说法是「和强基线相当、部分更好」，不是全面碾压。例如 tau3 Banking 它输给 DeepSeek Harness（49.48 对 55.67），OfficeQA Pro 和 BrowseComp 也不是第一。各基准差距多为一到几分，论文未给出多次运行的方差或置信区间，小差距需要谨慎看待。

RSI 后训练（Qwen3.6-35B-A3B，论文表 2，均为 0 到 100 分）：

| 基准 | R0 | R5 | 变化 |
|---|---|---|---|
| AutomationBench | 11.00 | 44.15 | +33.15 |
| BFCL v4 | 63.48 | 70.83 | +7.35 |
| OfficeQA | 55.64 | 62.11 | +6.47 |
| tau3 Banking | 14.43 | 22.68 | +8.25 |
| Harvey LAB | 3.33 | 11.08 | +7.75 |
| SkillsBench | 20.85 | 35.76 | +14.91 |
| GDPVal（评分规则得分） | 74.11 | 76.45 | +2.34 |
| JobBench | 22.66 | 20.53 | -2.13 |
| 八项平均 | 33.19 | 42.95 | +9.76 |

各轮平均分依次为 33.19、36.94、35.90、39.22、40.71、42.95，并非单调上升：R2 掉了一点，论文复盘发现 42 条长轨迹占了 84.2% 的监督 token，于是 R3 扩大数据覆盖。八项里七项高于起点，JobBench 反而下降。需要注意：每轮同时改了数据配方、起点检查点和训练策略，论文自己说明这些是并发干预，不是孤立的因果效应；提升最大的 AutomationBench 在 R3 的训练轨迹里占 78.3%，提示很大一部分收益可能来自针对性补数据，而不一定是跨任务泛化（论文自己则把七项超过基线解读为跨任务泛化的正面证据，该推断未经消融验证）。

定性案例：论文展示了 24 个应用案例（网页、游戏、Office 幻灯片、交互可视化、CAD、Blender），与 Codex 和 DSH 作截图对比。这些是作者挑选的观察，论文自己也强调不能据此推出成功率排名或模型正确性。

## 五、潜在应用与已落地应用

潜在方向：个人或团队的长期办公助理（写文档、做 PPT、建 CAD 和 Blender 模型，人随时直接改）；需要长期盯梢的任务（监控训练、跟踪外部信息）；智能体驱动的模型研发流程。

已核实的发布情况（2026-11-06 通过 GitHub API 查询）：

- 代码已开源：[RUC-NLPIR/CoworkOS](https://github.com/RUC-NLPIR/CoworkOS)，MIT 许可，仓库创建于 2026-11-03，最近提交 2026-11-03，已有 v0.1.3 发布，HF 页面显示约 131 个星标。
- 可通过 npm 包 coworkos-app 安装，README 写明提供 macOS 桌面版（Apple Silicon，macOS 14 以上）和命令行版；初始化时需要自己填写模型服务地址、模型 ID 和 API Key。npm 页面受 Cloudflare 验证拦截，无法读取，以上来自 GitHub README。
- [项目主页](https://coworkos-ai.github.io/)和[在线展示页](https://coworkos-ai.github.io/showcase.html)存在（主页已读取，展示页只确认了链接来自论文与 README）。
- HF 论文页没有关联的模型、数据集或 Space。RSI 后训练得到的模型权重和训练数据，我没有找到公开发布；仓库里有一个 issue 在询问[如何复现 RSI 后训练流程](https://github.com/RUC-NLPIR/CoworkOS/issues/4)，说明至少当时尚未提供现成的复现流程，具体答复我没有核对。
